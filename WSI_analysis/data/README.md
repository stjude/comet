# `data/`

This folder holds the **minimal-example data** used by every analysis in this repository, plus the scripts that generated it (`gen_*.py`). It exists to let a reviewer run the actual model-fitting code (see [`../core_code/README.md`](../core_code/README.md)) end-to-end on real, representative data, **without** distributing the full underlying cohort, raw whole-slide images, raw methylation matrices, or any clinical/identifying information.

## An important disclosure up front

**This is a subset, not the full cohort.** Every file here covers only a fraction of the samples used in the full study (typically a few hundred to a few thousand slides/samples, out of a much larger internal cohort), and in several cases only a single scale / a single foundation model / a reduced feature set is included (see each file's description below).

---

## Whole-slide image (WSI) representations
Below is the description of the representations provided. Due to their size they are saved on zenodo (https://zenodo.org/records/21997824). Please download and copy them here. Note rms_tiles and NB_tiles need to be unzipped

### `univ2_20x_sample_reps.p` — SAMPLER representations (all tiles, single scale)

A dictionary `{slide_filename: (10, 1536) float16 array}`. For each slide, every tile was embedded with the UNI-v2 tile-level foundation model at a single scale (20x-equivalent), and the 10 array rows are the 5th/15th/25th/.../95th percentile of that embedding **computed across all tiles of the slide**. This "SAMPLER" representation compresses an entire whole-slide image (which can contain tens of thousands of tiles) into one small, fixed-size, order-independent summary vector — the representation format that most of the WSI-based classifiers in this repo consume directly.

### `rms_tiles/`, `NB_tiles/` — individual tile-level representations (subsampled)

One pickle per slide (`<slide_id>.p`), each containing `{"tiles": (n_tiles<=1000, 1536) float16, "locs": (n_tiles, 2) int, ...}` — the *raw, per-tile* UNI-v2 embeddings (same foundation model/scale as above), **not** percentile-summarized, but randomly subsampled down to at most 1000 tiles per slide to keep the total data size manageable. `locs` records the pixel coordinates of each kept tile, which is what lets the tumor-indicator files below be matched back onto these exact tiles.

- `rms_tiles/` covers the RMS-subtype cohort (generated by `gen_rms_tiles.py`).
- `NB_tiles/` covers the neuroblastoma (NB) cohort used for MYCN-amplification prediction (generated by `gen_nb_tiles.py`).

These are the inputs to the tile-level analyses (`core_code/mil_classification_core.py`, `core_code/tile_level_classification_core.py`).

### `tum_mlda_clf.p` — pretrained tumor/non-tumor tile classifier

A small, already-fit `sklearn` `LinearDiscriminantAnalysis` model (a handful of KB) that scores a single tile as tumor vs. non-tumor from a tile-level feature vector. This is a **fixed artifact** used by `../core_code/tile_tum_detector.py` — nothing in this repository re-trains it. It contains only model weights; no patient data.

### `RMS_tumor_indicator.p`, `NB_tumor_indicator.p` — precomputed tumor/non-tumor tile masks

A dictionary `{slide_id: {(x, y): bool}}` — for every tile kept in `rms_tiles/` / `NB_tiles/` respectively, whether that tile was classified as tumor by `tum_mlda_clf.p`. Precomputing and caching this mask (rather than re-running the classifier every time a tile-level model is trained) keeps the tile-level classification code simple and fast, and makes tumor/non-tumor status a transparent piece of metadata rather than a hidden runtime side effect.

## Methylation representations

### `meth_top5000_sample_reps.p`

A dictionary with keys:
- `probe_ids` — list of 5,000 CpG probe identifiers,
- `sentrix_ids` — list of N sample identifiers (methylation array "Sentrix" IDs),
- `beta` — `(N, 5000)` `float16` array of SWAN-normalized methylation beta values,
- `metadata` — `{sentrix_id: {"comet_id": str, "slide": str or None}}`, linking each methylation sample back to a cohort ID and (if available) a matching WSI slide filename.

## Task-specific cohort metadata

These files exist so that a task-specific data-cleaning procedure (patient/sample inclusion criteria, label derivation, quality filtering) only has to be implemented and reasoned about once, in one script, rather than being re-implemented — and potentially re-diverging — inside every downstream training/evaluation script.

### `RMS_survival_metadata.p`

The cleaned rhabdomyosarcoma (RMS) survival cohort used by `../RMS_survival/`. A dictionary with:
- `Y` — a `(N, 14)` array of per-sample outcome/clinical columns (overall survival time, vital status, molecular subtype, age, several treatment/staging fields, risk group, and a derived 3-year-mortality label),
- `lab_ind` — the column index of the 3-year-mortality label within `Y`,
- `labels` — the 14 column names, in order,
- `slides` — the matching WSI slide filename for each row,
- `sentrix` — the matching methylation sample identifier for each row (empty string if none),
- `patient_ids` — a cohort-internal patient identifier for each row (**not** a hospital medical record number or any other externally-meaningful identifier).


### `NB_ADRN_MES_slides.p`

The final slide-level cohort and binary label used by `../NB_ADRN_MES/` for adrenergic (ADRN) vs. mesenchymal (MES) neuroblastoma classification. A dictionary with `slides` (list of WSI filenames), `labels` (`0`=ADRN, `1`=MES), and `label_meaning`.

## How this connects to the rest of the repo

Nothing in this folder trains or evaluates a model — see [`../core_code/README.md`](../core_code/README.md) for the model-fitting logic that consumes these files, and the per-task READMEs (`../tumor_classification/`, `../RMSsubtyping/`, `../NB_MYCN/`, `../RMS_survival/`, `../NB_ADRN_MES/`) for how each task's wrapper script points the core code at the specific files described above.
